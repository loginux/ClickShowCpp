# ClickShowCpp 概要设计

本文描述 ClickShowCpp 的整体结构、关键实现决策和约束，面向需要修改代码或排查问题的人。功能列表与版本变更见 [README](../README.md)。

- 文档版本：对应程序 1.51
- 适用范围：`src/`、`res/`、`tests/`、构建脚本

---

## 1. 概述

| 项 | 说明 |
|---|---|
| 目标平台 | Windows 10 / 11 x64 |
| 技术栈 | C++20 + Win32 + GDI+，`/MT` 静态 CRT，单个 exe，无 .NET 依赖 |
| 全局输入 | Raw Input（`RIDEV_INPUTSINK`），不用低级钩子 |
| 界面 | 一个设置对话框 + 托盘图标 + 两个覆盖层窗口 |
| 持久化 | 与原版 C# 版字节级兼容的 JSON |
| 后台 | 无服务、无驱动、无注入；唯一的全局监听是 Raw Input |

两个覆盖层窗口：

1. **波纹**：按键按下/抬起时以光标为中心画一个扩散并淡出的圆环。
2. **浮标**：跟随光标的小圆点，用于提示当前位置。

两者都是点击穿透（`WS_EX_TRANSPARENT`）、不抢焦点（`WS_EX_NOACTIVATE`）、置顶（`WS_EX_TOPMOST`）的分层窗口（`WS_EX_LAYERED`），并通过 `WDA_EXCLUDEFROMCAPTURE` 从截图/录屏中排除。

| `src/settings.cpp` | `ClickShow.setting` JSON 读写、旧 INI 迁移与兜底 | `json`、`util` |
| `src/counts.cpp` | `ClickShow.counts` JSON 读写、旧 INI 迁移与兜底 | `settings`、`json`、`util` |

## 3. 线程模型

### 3.1 UI 线程（唯一拥有窗口）

`wWinMain` 创建主对话框，之后所有窗口都在这个线程：

- Raw Input 的 message-only 窗口（`HWND_MESSAGE`）在同一线程创建，`WM_INPUT` 由该线程的消息循环分发；
- `WM_TIMER`（设置防抖、计数落盘、截图恢复、覆盖层合帧）也在这里；
- `WM_COMMAND`、托盘回调同样在这里。

因此 `g_settings`、`g_counts`、`g_buttonStates`、`Overlay` 的内部状态**全部单线程访问，不需要加锁**。这是刻意设计：加锁会把输入热路径变复杂，且没有必要。

新增共享状态前必须先判断它属于哪个线程；若确实跨线程，用下面的模式。

### 3.2 更新检查线程

唯一的后台线程，只做一件事：拉取版本信息。

```
UI 线程                                  工作线程
  StartUpdateCheck()
    CreateEvent(手动重置)  ───────────────►  WaitForSingleObject(event, 10s)
    std::thread(...)                          ├─ 被 SetEvent 唤醒 → 直接退出
                                              └─ 超时 → IsWindow + g_exiting 检查
                                                   → WinHTTP 请求（3s 超时）
                                                   → 结果写入 g_updateResult（互斥量保护）
                                                   → PostMessage(仅作信号，不带指针)
  kUpdateMessage ──────────────────────►  取走结果并弹窗
  StopUpdateCheck(): SetEvent + join
```

要点：

- 结果是 `std::unique_ptr<UpdateResult>`，放在 `g_updateMutex` 保护的全局槽里；**消息的 `lParam` 不携带指针**，避免窗口销毁后句柄被复用时把裸指针投递给别人。
- `g_exiting` 是 `std::atomic<bool>`，工作线程在等待结束、发请求前、投递结果前各检查一次。
- 退出时先 `SetEvent` 再 `join`，不会留下游离线程在静态 CRT 拆卸期间继续调用 CRT。
- WinHTTP 超时设为 3 秒，避免服务器无响应时退出被拖住。

### 3.3 覆盖层定时器

动画不用独立线程，而是挂在主窗口上的 `SetTimer(kOverlayTimerId, 16ms)`：

- `Overlay::ShowRipple()` / `UpdateHover()` 调用 `EnsureTimer()` 启动；
- `Tick()` 里没有活跃波纹、也没有待处理的 hover 更新时 `StopTimerIfIdle()` 停掉；
- 鼠标持续移动期间**保持定时器存活**——每个 `WM_INPUT` 都 `SetTimer`/`KillTimer` 反而更贵。

合帧的意义：高回报率鼠标每秒可产生上千个输入包，统一压到约 60fps 渲染。

## 4. 输入处理

### 4.1 注册

```cpp
RAWINPUTDEVICE devices[2];
devices[0] = {0x01, 0x02, RIDEV_INPUTSINK, hwndMessageOnly}; // mouse
devices[1] = {0x01, 0x06, RIDEV_INPUTSINK, hwndMessageOnly}; // keyboard
```

`RIDEV_INPUTSINK` 让程序在前台属于别的进程时也能收到输入。目标窗口是 message-only 窗口，必须属于调用线程。停止时用 `RIDEV_REMOVE` 注销。

### 4.2 按键映射

Raw Input 用位标志区分 5 个按键，映射到 `InputButton`：

| Raw Input 标志 | 按钮 | `ButtonIndex` |
|---|---|---|
| `RI_MOUSE_LEFT_BUTTON_*` | 左键 | `kLeft = 0` |
| `RI_MOUSE_MIDDLE_BUTTON_*` | 中键 | `kMiddle = 1` |
| `RI_MOUSE_RIGHT_BUTTON_*` | 右键 | `kRight = 2` |
| `RI_MOUSE_BUTTON_4_*` | 侧键后退 | `kX1 = 3` |
| `RI_MOUSE_BUTTON_5_*` | 侧键前进 | `kX2 = 4` |

配置文件里的 `Key` 是原版的枚举数值（1048576 / 4194304 / 2097152 / 8388608 / 16777216），集中定义在 `settings.h` 的 `kMouseButtonKeys`，两个存储模块共用，不再各写一份。

### 4.3 抬手波纹的判定

按下时记录时间与坐标；抬起时满足以下任一条才再画一个小波纹：

- 位移超过 **200 逻辑像素**（按光标所在显示器 DPI 缩放为物理像素）
- 按住超过 **500ms**

这样"点一下"只有一个波纹，拖拽/长按会有第二个。

### 4.4 光标位置过滤

`WM_INPUT` 对按键、滚轮也会投递。只有 `GetCursorPos()` 的坐标相对上一次确实变化时才触发 `onMove`，否则每次点击都会重画浮标、唤醒定时器。

## 5. 渲染与 DPI

### 5.1 表面与呈现

每个覆盖层窗口持有一套：

```
CreateDIBSection(32bpp, 负高度)  →  HBITMAP + 像素指针
CreateCompatibleDC + SelectObject
Gdiplus::Bitmap(width, height, stride, PixelFormat32bppPARGB, bits)
Gdiplus::Graphics(bitmap)
UpdateLayeredWindow(hdcMem, ..., AC_SRC_ALPHA)
```

GDI+ 直接画进 DIB，`UpdateLayeredWindow` 负责呈现。窗口尺寸变化时才重建表面。

### 5.2 波纹

- 时长：按下 400ms，抬起 300ms。
- 半径：按下 `0.2 → 1.0`，抬起 `0.5 → 1.0`。
- 透明度：`(1 - progress) × 窗口不透明度(0.95/0.7) × 按钮 alpha`。
- 每帧重绘（动画必须）。
- 用最多 32 个窗口的对象池；全部活跃时轮转复用。

### 5.3 浮标

- 内容是一张**静态图**：只在尺寸、颜色、透明度变化，或表面重建后才重绘。
- 光标移动只更新分层窗口位置，不重画。
- 只有首次显示（或从隐藏恢复）时才 `SetWindowPos(..., SWP_SHOWWINDOW)` 并设置一次 `WDA_EXCLUDEFROMCAPTURE`；之后每帧用 `SWP_NOREDRAW` 移动，重绘交给 `UpdateLayeredWindow`。

### 5.4 DPI

- 物理尺寸 = `MulDiv(逻辑尺寸, dpi, 96)`，最小 4px（浮标）/ 8px（波纹）。
- DPI 按光标所在显示器取：`MonitorFromPoint` + `GetDpiForMonitor(MDT_EFFECTIVE_DPI)`；老系统回退到 `GetDpiForWindow` / 屏幕 DC。
- 结果按显示器缓存一条，`WM_DISPLAYCHANGE` / `WM_DPICHANGED` 时失效。
- 设置对话框本身没有做 per-monitor 重排（见「已知限制」）。

## 6. 配置与计数持久化

### 6.1 加载结果三态

`SettingsStore::Load()` 返回三种状态之一，只有一种会覆盖文件：

| 状态 | 触发条件 | 行为 |
|---|---|---|
| `Ok` | 文件存在、可读、JSON 合法 | 使用文件内容 |
| `Unavailable` | 打不开、被占用、权限不足、`exists()` 报错 | 内存里用默认值，置 `writeBlocked_`，**禁止任何写回**（含退出保存） |
| `Corrupt` | 读到了但不是合法 JSON 对象 | 默认值 + 弹窗 + 立即保存（与原版行为一致） |

计数用同样的三态思路，`loadFailed_` 阻止周期性保存把损坏/读不到的文件覆盖成 0；用户点"重置计数"会清除该标志（显式操作允许写）。

### 6.2 INI 兜底链路

第一版 C++ 版用 INI，现在只作为兜底：

```
保存: JSON 写入失败 → 写 <file>.ini（含 #AARRGGBB 颜色与独立 alpha 键）→ 置 [fallback] pending=1
加载: INI 存在且 pending=1 → 读 INI → 写回 JSON 成功 → pending=0
     否则 → 正常读 JSON
```

标记是必要的：如果只按"JSON 是否存在"判断，旧 JSON 还在时兜底数据永远读不回来，那次的修改就静默丢失了。

### 6.3 写入时机

| 触发 | 原版 C# | C++ 版 |
|---|---|---|
| 任意设置属性变化 | 100ms 防抖（ApplicationIdle）→ `SaveSettings()` → `ApplySettings()` | 100ms `WM_TIMER` → 保存设置 JSON → 应用覆盖层 |
| 更新提示 | 先写入原始版本字符串 `LastNotifiedVersion` 并保存，再弹窗 | 相同；保存 `raw`（版本与 url 以竖线分隔），弹窗前写入 |
| 启动加载 | 文件有效不写；损坏时弹窗 + 默认值 + 立即保存 | 相同；只有真正损坏才弹窗并保存 |
| 关闭窗口/最小化 | 只隐藏，不保存 | 相同 |
| 退出（托盘/按钮） | `OnClosed`：先保存设置，再停钩子，最后保存计数 | `WM_DESTROY`：同样的顺序 |
| 注销/关机 | 无 | `WM_ENDSESSION`：立即保存设置与计数（系统可能不再发 `WM_DESTROY`） |
| 点击计数 | 只在内存 `++`，不落盘 | 相同 |
| 计数定时落盘 | 10 分钟 DispatcherTimer | 10 分钟 `WM_TIMER` |
| 重置计数 | 确认后 Reset + Save | 相同 |
| 开机自启 | 只写 HKCU Run，不写设置文件 | 相同；路径加引号并校验指向自身 |

写入频率实测（开发机）：

| 场景 | 写入次数 |
|---|---|
| 2 秒内 40 次滑块变化 | 1 次（停手后） |
| 20 次快速复选框连点 | 1 次（停手后） |
| 正常点击鼠标 | 0 次（仅内存累加） |

### 6.4 原子写

`WriteFileAtomicUtf8` 写 `<file>.<pid>.tmp`，`MoveFileEx(MOVEFILE_REPLACE_EXISTING)` 替换。带 PID 是为了避免两个实例撞同一个临时文件。不调用 `FlushFileBuffers`，配置文件很小，按普通缓存写即可。

### 6.5 兼容性约束

- 字段名、顺序、数值格式必须与原版 `DataContractJsonSerializer` 一致；`LastNotifiedVersion` 为空时写 `null`。
- 颜色按 `#AARRGGBB` 读写，alpha 必须保留（Win32 `ChooseColor` 只能改 RGB）。
- 计数文件保存顺序是 **Left, Right, Middle, X1, X2**（原版顺序），与设置文件的 Left, Middle, Right 顺序不同，两者不要混用。
- 不要同时运行 C# 版和 C++ 版：两边各自在内存维护设置与计数，后保存的会覆盖先保存的。

### 6.6 JSON 解析器

自带的极简解析器只需要覆盖配置文件：对象、数组、字符串、数字、布尔、`null`，支持 `\uXXXX` 转义。硬性上限：

- 嵌套深度 **64 层**（防止损坏或恶意文件把栈打爆）；
- 单个文件读取上限 **16MB**；
- UTF-8 解码使用 `MB_ERR_INVALID_CHARS`，非法字节直接判定为损坏，而不是静默替换。

## 7. 与 C# 版的差异

| 方面 | C# 版 | C++ 版 |
|---|---|---|
| 语言与运行时 | C# + WPF，.NET Framework 4.7.2 | C++20 + Win32 + GDI+，静态 CRT，单个 exe |
| 输入 | `WH_MOUSE_LL` 低级钩子，跑在 UI 线程 | Raw Input（`RIDEV_INPUTSINK`），无钩子超时问题 |
| 渲染 | WPF 透明窗口 | Win32 layered window + GDI+ |
| 截图 | PrintScreen 后隐藏 1 秒 | `WDA_EXCLUDEFROMCAPTURE` + PrintScreen 回退 |
| 点击计数 | 无 | 5 键 + 合计，10 分钟/退出/重置落盘 |
| 单实例 | 无 | 命名 Mutex（`Local\ClickShowCpp.SingleInstance`） |
| 配置 | JSON（`我的文档`） | 相同 JSON，字节级兼容 |
| 计数 | JSON | 相同 JSON |
| 更新检查 | 后台线程 | 后台线程 + 可取消 + 退出时 join |
| alpha | ColorPicker 可编辑 | 保留原值（Win32 颜色对话框不能改 alpha） |

## 8. 版本机制

- 唯一真源：`src/version.h` 的 `CLICKSHOW_VERSION_WSTRING`。
- CMake 与 `build.cmd` 都解析这一行，生成 `app.rc` 的 `FILEVERSION`/`ProductVersion` 和 `app.manifest` 的 `assemblyIdentity`。
- `VERSIONINFO` 与 `assemblyIdentity` 都要求 **4 段**版本号，脚本会把 `1.51` 补成 `1.51.0.0`、`1,51,0,0`。
- 更新检查用 `CompareVersions` 逐段按数值比较（非数字字符忽略）。

> 版本号语义提醒：`1.51` 的次版本号是 **51**，因此它比 `1.6` 新。升到 1.51 之后的版本号必须 ≥ `1.52`，否则更新检查会认为比当前版本旧。

## 9. 构建系统

### 9.1 两条构建链

| 脚本 | 生成器 | 产物 | 说明 |
|---|---|---|---|
| `build.bat` | CMake + Ninja | `build\ClickShow.exe` | 增量构建；配置失败时清空缓存重试 |
| `build.cmd` | `cl` + `rc` 直接编译 | `build_direct\ClickShow.exe` | 不依赖 CMake/Ninja |

两者都从 `src/version.h` 取版本，生成资源脚本和清单，行为保持一致。

### 9.2 关键编译选项

```
/W4 /permissive- /utf-8 /EHsc        警告与语言行为
/DUNICODE /D_UNICODE /DNOMINMAX      Unicode + 关掉 min/max 宏
/DWIN32_LEAN_AND_MEAN /D_WIN32_WINNT=0x0A00
/MT                                 静态 CRT
/MANIFEST:NO                        清单由 app.rc 嵌入，不让链接器再生成
```

### 9.3 生成资源

```
res/app.rc.in      ── configure_file（@CLICKSHOW_ICON@ 等）──► build/app.rc
res/app.manifest   ── configure_file（@CLICKSHOW_VERSION_FULL@）──► build/app.manifest
```

`res/` 下的这两个文件是**模板**，不能直接用 `rc.exe` 编译。

### 9.4 生成器注意事项

CMake 4.4.0-rc3 的 `NMake Makefiles` 生成器在本机会生成 `$(MAKE) ... -$(MAKEFLAGS)`，`MAKEFLAGS` 为空时 `nmake` 报"无效选项 -"，所以默认用 Ninja。

Visual Studio 生成器：

```bat
cmake -S . -B build-vs -G "Visual Studio 18 2026" -A x64
cmake --build build-vs --config Release
```

输出在 `build-vs\Release\ClickShow.exe`。

### 9.5 测试

```bat
build.bat -DCLICKSHOW_BUILD_TESTS=ON
ctest --test-dir build --output-on-failure
```

`ConfigTest` 覆盖：设置/计数往返、字节稳定性、原版 JSON 乱序与未知字段、alpha 保留、INI 兜底恢复、不可读文件不被覆盖、JSON 嵌套深度、代理对、版本比较。测试只读原版配置，临时文件写在 `build_direct\config_test\`。

## 12. 已知限制

- 目标为 Windows 10/11 x64。`WDA_EXCLUDEFROMCAPTURE` 需要 Windows 10 2004+；更老的系统只走 PrintScreen 隐藏回退。
- 设置窗口没有做完整的 per-monitor 重排（移动到不同 DPI 显示器时不会按新 DPI 重新缩放控件）；覆盖层是按 DPI 计算的。
- `ReleaseElevated`/UIAccess 不在此版本中；默认以普通用户运行。
- 未做代码签名，SmartScreen 可能提示。
- 更新检查只打开浏览器，不自动下载安装。
- Win32 颜色对话框不编辑 alpha；per-button/hover 的 alpha 会保留原值。
- 不要同时运行 C# 版和 C++ 版，否则设置/计数会互相覆盖。
- 全局键盘 `RIDEV_INPUTSINK` 只用于检测 PrintScreen/Win+Shift+S，但行为上等同键盘监听，个别 EDR 可能误报；移除它会失去旧系统的截图回退。
- 计数界面的静态文本宽 30 DLU，7 位以上数字会被截断（仅显示问题，文件里的值不受影响）。
- 配置文件不可读时（`Unavailable`），用户的设置改动只存在于内存，退出即丢；目前只记录日志，没有 UI 提示。
